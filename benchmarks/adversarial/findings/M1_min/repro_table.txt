Full enumeration of non-string inputs that crash compute_check_digits
at iban-pure v0.1.0 @ commit 4bf40d0 (cycle_67, audited by cycle_67/01 §4.2 M1).

Each row below is reproducible with a 1-line Python invocation:

  python -c 'from iban_pure import compute_check_digits; compute_check_digits(<input>)'

The minimal repro for triage purposes is the None case (most likely
caller mistake); the table is the full enumeration audit captured.

Compare to validate() (which has the isinstance guard) on the SAME inputs:
  validate(<input>) returns False for ALL of the above. Zero raises.

This asymmetry is the design defect. The audit recommended:
  - Add `if not isinstance(bban, str): raise ValueError(...)` at the
    top of compute_check_digits, mirroring validate()'s policy of
    "raise the documented ValueError, not an internal AttributeError."

Severity rationale (Medium, not High):
  - CWE-754 (Improper Check for Unusual or Exceptional Conditions)
  - Cannot crash a host process; only crashes a caller that wraps
    compute_check_digits in `try/except ValueError` and assumes
    AttributeError never fires.
  - No data corruption, no privilege escalation, no DoS.
  - Audit explicitly DEFERRED to next patch as "defensive-coding only".
